## 2. Мета та користувачі

Цей бекенд створено як серверну частину інтернет-магазину дронів, що обслуговує:
- авторизацію та реєстрацію користувачів;
- роботу з товарами та категоріями;
- замовлення та адреси доставки;
- верифікацію електронної пошти через Gmail SMTP;
- безпечну взаємодію через JWT та Prisma.

Проєкт корисний для:
- розробників, що створюють e-commerce бекенд на Node.js та TypeScript;
- студентів, які вивчають роботу з JWT, Prisma і REST API;
- команд, що будують системи замовлень, керування товарами та профілів користувачів.

## 6. Розгортання проєкту на локальному ПК

### Windows

1. Відкрити PowerShell або Windows Terminal.
2. Перейти до каталогу, де хочете зберегти репозиторій:
```powershell
cd C:\Projects
```
3. Клонувати репозиторій:
```powershell
git clone https://github.com/your-username/DronesShopTeam3.git
cd DronesShopTeam3
```
4. Перевірити, що в корені є `package.json` та `prisma/schema.prisma`.
5. Встановити залежності:
```powershell
npm install
```
6. Створити файл конфігурації оточення `.env` на основі `.env.example`.
7. Синхронізувати базу даних:
```powershell
npx prisma db push
```
8. Запустити сервер:
```powershell
npm start
```

## 7. Налаштування віртуального оточення на вашому ПК

Цей бекенд використовує Node.js та TypeScript. Щоб запустити фронтенд, дивіться репозиторій `../dones-frontend-team3`.

### Windows

1. Перевірити наявність Node.js:
```powershell
node -v
npm -v
```
2. Якщо Node.js не встановлено, скачати та встановити з сайту https://nodejs.org/en/download/.
3. Якщо потрібно керувати кількома версіями Node — встановіть `nvm-windows`.
4. У корені бекенд-проєкту виконайте:
```powershell
npm install
```

### macOS

1. Перевірити Node.js:
```bash
node -v
npm -v
```
2. Якщо Node.js не встановлено, використайте Homebrew або офіційний інсталятор:
```bash
brew install node
```
3. Опціонально: встановіть `nvm` і виберіть стабільну версію:
```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.4/install.sh | bash
nvm install --lts
nvm use --lts
```
4. У корені бекенд-проєкту встановити залежності:
```bash
npm install
```

## 9. Особливості розробки

### Работа з зображеннями

У цьому бекенді збереження зображень виконується через поля моделі продукту та опису продукту.
- Поле `img` у моделі `Product` зберігає URL зображення або шлях до файлу.
- Поле `img` у моделі `ProductDescription` використовується для ілюстрації характеристик товару.
- Фізичне завантаження файлів не реалізоване на поточному етапі; бекенд працює із посиланнями на зображення.

### Работа з веб-сокетами

У цьому бекенді веб-сокети не реалізовані. Сервер працює як REST API на основі Express, а синхронізація відбувається через HTTP-запити.

### Принцип роботи постів, альбомів, налаштувань, чатів

Цей бекенд призначений для інтернет-магазину, тому функції соціальної мережі (пости, альбоми, чати) не реалізовані.

Реально реалізований функціонал:
- керування товарами (`GET /products`, `POST /products`, `PATCH /products/:id`, `DELETE /products/:id`);
- керування категоріями (`GET /category`, `POST /category`, `PATCH /category/:id`, `DELETE /category/:id`);
- робота з замовленнями та адресами користувача (`POST /user/order`, `PATCH /user/order/:id`, `DELETE /user/order/:id`, `POST /user/adress`, `PATCH /user/adress/:id`, `DELETE /user/adress/:id`).

### Работа з AJAX

У фронтенді клієнт може звертатися до бекенду через AJAX-запити (`fetch` або `axios`) до REST-ендпоінтів сервера.
- Сервер повертає JSON у відповідь на `GET`, `POST`, `PATCH`, `DELETE`.
- Наприклад, `GET /products` повертає список товарів, а `POST /products` створює новий товар.
- `suggestions`-ендпоінт підтримує параметри `skip`, `take`, `new`, `popular` та `sameAs` для гнучкого фільтра.

### Принцип роботи реєстрації та авторизації

Реєстрація та авторизація працюють через JWT та хешування паролів:
- `POST /user/registration` — створення користувача, хешування пароля через `bcrypt`, та видача JWT токена з терміном дії 7 днів.
- `POST /user/login` — перевірка електронної пошти, порівняння пароля з хешем і видача JWT токена з терміном 30 днів.
- Захищені маршрути використовують `authMiddleware`, який перевіряє заголовок `Authorization: Bearer <token>` та передає токен у `res.locals.token`.
- `GET /user/me` повертає дані користувача без пароля.

## 10. Висновок

Цей бекенд-проєкт був корисним і практичним кейсом для закріплення навичок побудови серверної частини на Node.js + TypeScript з використанням Express та Prisma. Під час розробки я працював над кількома важливими напрямками:

- **Архітектурне розділення**. Розподіл на контролери, сервіси та репозиторії зробив код більш структурованим та зручним для підтримки. Це дозволило не захаращувати `server.ts` бізнес-логікою, а зосередити її в окремих модулях.
- **Безпека автентифікації**. Я реалізував `bcrypt` для хешування паролів та `jsonwebtoken` для видачі безпечних JWT токенів. Такий підхід захищає паролі користувачів і дозволяє легко контролювати доступ до захищених ресурсів.
- **Prisma як ORM**. Використання Prisma дозволило швидко працювати з базою даних SQLite, легко описувати зв’язки моделей та виконувати складні запити. Це особливо корисно для роботи з відношеннями: `User` → `Adress`, `User` → `Order`, `Order` → `OrderProduct`, `Product` → `Category`.
- **EMail-верифікація**. Налагодження надсилання листів через Gmail SMTP дало зрозуміти, як будуються серверні email-оповіщення. Це важливий елемент сучасних систем, де підтвердження електронної пошти або відновлення пароля є частиною безпеки.
- **Робота з даними користувача**. Я реалізував CRUD для адрес користувача, замовлень та оновлення даних профілю. Це дозволило глибше зрозуміти, як будувати ланцюжки бізнес-логіки і як пов’язувати записи в базі даних через Prisma.

За допомогою цього проекту я зміг практично перевірити, як виконуються такі задачі:
- аутентифікація, коли сервер видає токен і повторно перевіряє його на захищених маршрутах;
- оновлення даних в моделях з різними зв’язками, що важливо для реальних бізнес-завдань;
- робота з транзакційними об’єктами та обробка помилок Prisma, наприклад `P2024`.

Цей бекенд корисний, оскільки він не просто демонструє базову CRUD-логіку, а також показує спосіб інтеграції з реальними сервісами: email-повідомлення, JWT-токени та відносно складна модель даних для замовлень. Він може стати основою для більш масштабного застосунку, де додатково можна підключити:
- збереження фотографій продуктів через S3 або локальний `multer`;
- WebSocket для оновлення статусу замовлення в реальному часі;
- інтеграцію з платіжними сервісами;
- розширення моделі користувачів, наприклад, ролі, права доступу та історію змін.

Підсумок: створення цього проєкту допомогло не тільки поглибити розуміння Node.js та Express, а й сформувати правильний підхід до побудови повноцінного серверного API. Далі цей бекенд можна масштабувати на production, підключивши PostgreSQL, додавши логування та розширення бізнес-функціональності.
